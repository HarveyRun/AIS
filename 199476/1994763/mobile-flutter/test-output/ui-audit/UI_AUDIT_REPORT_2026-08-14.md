# Flutter 移动端 UI / 交互 / 排版核对报告

核对日期：2026-08-14

基准：项目根目录中的原 React Web 移动端

核对对象：`mobile-flutter`

## 结论

当前 Flutter 版本与原 Web 移动端并不完全一致。

页面和核心业务入口大体齐全，但视觉一致性较低，部分页面的交互结构和业务内容也发生了变化。Flutter 当前大量使用默认 Material 组件样式，导致字号、卡片高度、边框、留白、底部导航、表单和弹层呈现出另一套设计语言。以美观为第一标准时，原 Web 的信息密度、层级和整体完成度明显更成熟。

因此，当前 Flutter APK 可以用于功能联调，但不应作为视觉完成版交付。

## 核对范围

- 原 Web：15 个主要页面截图
- Flutter 真机：21 个页面或交互状态截图
- 静态核对：路由、主题、导航、表单、钱包、认证、询问、聊天、客服等页面源码
- 真机尺寸：1080 × 2400，系统字体缩放 1.0

截图位置：

- 原 Web：`test-output/ui-audit/web`
- Flutter：`test-output/ui-audit/flutter`

## 必须先修的问题

| 页面/模块 | 发现的问题 | 影响 |
| --- | --- | --- |
| 验证码登录 | 软键盘打开时出现 `BOTTOM OVERFLOWED BY 15 PIXELS`；页面同时保留自动提交和“登录”按钮，交互重复 | 真机可见的排版错误 |
| 全局导航 | 原 Web 除聊天和在线客服外，二级页面仍保留底部导航；Flutter 的发现、钱包、认证、设置、反馈、常见问题、通知等二级页面全部失去底部导航 | 导航逻辑不一致，切换主功能更麻烦 |
| 账户余额 | Flutter 把收支、提现记录、充值、提现做成 4 个横向分段项；真机首屏只能明显看到前三项，“提现”入口需要横向滑动且没有提示 | 关键资金入口不明显 |
| 投诉与反馈 | 原 Web 有“反馈内容 / 我的提交”和历史记录状态；Flutter 只有填写与提交，没有“我的提交”列表 | 功能不完整 |
| 常见问题 | Flutter 使用另一套硬编码问题；与原 Web 当前内容不一致 | 内容业务不一致 |
| 账号设置 | 原 Web 昵称限制为 12 个字符，Flutter 为 20 个字符 | 前后端及双端规则不一致 |

## 全局视觉问题

1. 字号和控件整体偏大。同一屏能展示的信息明显少于原 Web，容易产生“老人版 App”的观感。
2. 页面普遍采用默认 `AppBar`、`Card`、`ListTile`、`SegmentedButton`、`FilledButton`，默认 Material 感过强，没有延续原 Web 已形成的品牌风格。
3. 卡片高度、圆角和边框使用过多，页面显得笨重；发现列表、认证列表、设置页存在大片无效留白。
4. Flutter 底部导航使用整条浅粉背景和大号选中胶囊；原 Web 是更轻、更干净的白色导航，Flutter 抢占了页面主内容注意力。
5. 表单输入框和主按钮普遍过高，钱包、反馈、商务合作、账号设置等页面显得粗重。
6. 页面标题和正文层级拉得过大，视觉节奏不够紧凑。
7. 暗黑主题虽能正常阅读，但底部导航偏棕、图标偏粉，与主题红及页面内容不够统一。

## 已经保留正确的部分

- 首页顶部头像、主职搜索和消息入口
- Banner 10 秒轮播
- 首页人员分页加载和搜索
- 按事情、按经历两条查找路径
- 询问列表的发起/收到 Tab、未读提示、状态、金额和最后聊天时间
- 聊天页面隐藏全局导航，顶部和输入区固定
- 文本、图片、表情和实时消息能力
- 身份认证固定三张现场拍摄
- 岗位认证仅现场录像或现场照片二选一
- 经历认证的压缩包、录像和照片规则
- 钱包冻结金额、充值、提现和银行卡绑定业务入口
- 明亮和暗黑主题切换
- 接口重复请求合并机制

## 建议的修正顺序

1. 先统一全局视觉基础：字号、间距、圆角、卡片、按钮、表单、顶部栏、底部导航。
2. 优先重做高频页面：首页、我的、我的询问、聊天、个人档案、账户余额。
3. 修复验证码键盘溢出、全局导航范围、钱包入口、反馈记录、FAQ 内容、昵称限制。
4. 再统一发现、认证、设置、客服等二级页面。
5. 最后用真机逐页回归明亮/暗黑主题、键盘态、空状态、加载态、错误态和长文本状态。

修正时应以“整体美观和成熟 App 感”为第一标准，同时保持原 Web 的信息层级与业务入口，不机械复制不适合 Flutter 的浏览器细节。
