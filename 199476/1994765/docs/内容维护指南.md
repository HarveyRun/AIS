# 内容维护指南

本站所有内容都在 `content/` 目录下，**维护内容不需要写代码**，只需要编辑 JSON 文件。保存后运行校验，通过即可发布。

## 日常：修订一个已有项目

1. 打开 `content/countries/<国家>/programs/<slug>.json`
2. 修改对应字段（费用变了改 `cost`，政策变了改 `requirements` / `duration.steps`）
3. **务必更新 `infoVerifiedAt` 为你核实信息的日期**（页面会显著展示这个日期）
4. 运行 `npm run content:check`，看到 ✅ 即可；`npm run build` 出新版本

## 新增一个移民项目（最常见的任务）

在目标国家的 `programs/` 目录新建 `<slug>.json`，slug 用小写字母+中划线，建议格式 `<国家>-<省州?>-<名称>`，如 `ca-on-oinp-employer`、`au-190`。

完整字段模板（复制后填空）：

```jsonc
{
  "slug": "ca-on-oinp-employer",          // 必须与文件名一致
  "name": "安省省提名 · 雇主担保",
  "nameEn": "OINP Employer Job Offer Stream",
  "country": "canada",                     // 必须是已存在的国家 id
  "region": "ontario",                     // 省州级项目必填；联邦项目省略此行
  "type": "employer",                      // skilled|employer|business|talent|family|study
  "status": "active",                      // active|paused|archived（可省略，默认 active）
  "summary": "一句话概括，列表页展示",
  "suitableFor": "适合什么样的人",
  "difficulty": "mid",                     // low|mid|high
  "highlights": ["亮点1", "亮点2", "亮点3"],
  "requirements": [{ "title": "条件标题", "detail": "详细说明" }],
  "cost": {
    "note": "费用口径说明（可省略）",
    "breakdown": [{ "item": "官方规费/开销项", "amount": "具体金额，如「约 1,525 加元/成人」", "note": "备注（可省略）" }]
  },
  "duration": {
    "note": "周期口径说明（可省略）",
    "steps": [{ "title": "步骤名", "detail": "做什么", "durationHint": "约 3-6 个月" }]
  },
  "materials": ["材料1", "材料2"],
  "officialSources": [{ "label": "官方页面名称", "url": "https://..." }],
  "pros": ["优点（事实性）"],
  "cons": ["缺点 / 注意点（事实性）"],
  "infoVerifiedAt": "2026-09-22"           // 你核实信息的日期，必填
}
```

> ⚠️ **禁止出现「总费用 xx–yy 万」「总周期 x–y 年」这类拍脑袋区间**——范围大到没有信息量。
> 费用只写可核实的官方规费与主要开销项（amount 用具体数字），周期只标在每个流程步骤上。

## 新增一个省/州

在 `content/countries/<国家>/regions/` 下新建 `<region-id>.json`：

```json
{
  "id": "saskatchewan",
  "country": "canada",
  "name": "萨斯喀彻温省",
  "nameEn": "Saskatchewan",
  "summary": "一句话概述",
  "policyOverview": "该省移民政策的长文概述：主要通道、偏好人群、近年趋势。",
  "officialSite": "https://..."
}
```

## 新增一个国家

1. 建目录 `content/countries/<id>/`，写 `country.json`（字段见 `australia/country.json`）
2. 按需建 `regions/` 与 `programs/` 子目录
3. 新国家的国旗放 `public/flags/<id>.svg`（Windows 浏览器不渲染旗帜类 emoji，站点用本地 SVG；未放则回退显示 emoji 字符）

## 术语表

编辑 `content/glossary.json`。每条术语标注适用国家、分类与重要度；页面按国家/省州筛选、按分类分组、组内按重要度排序（必知 → 重要 → 了解）：

```jsonc
{
  "term": "CSQ",
  "en": "Labour Market Impact Assessment",   // 英文全称（可省略）
  "countries": ["canada"],                   // 适用的国家 id；通用术语填全部三个国家
  "category": "regional",                    // general 通用 | business 业务 | regional 地区特有
  "importance": "must",                      // must 必知 | important 重要 | optional 了解（组内排序依据）
  "regions": ["quebec"],                     // 仅省州专属术语需要标注；可省略
  "explanation": "一句到两句的事实性解释"
}
```

分类口径：**通用**＝各国通用的身份与材料概念；**业务**＝申请流程与制度机制（EOI、打分制、LMIA、I-140 等，含国家特有制度，用 countries 标注归属）。省/州专属术语（如 CSQ、ROI）再用 regions 标注到具体省州。

## 站点信息与免责声明

编辑 `content/site.json`（站名、标语、描述、免责声明、维护者署名）。

## 校验规则速查

以下问题会被 `npm run content:check` 拦下（并给出具体文件与字段）：

- JSON 语法错误、必填字段缺失、字段名拼写错误
- `country` / `region` 引用了不存在的 id
- 项目 slug 与文件名不一致、slug 全局重复
- 日期不是 `YYYY-MM-DD`、URL 不合法

## 内容质量守则

1. **只写可核实的内容**：费用只写官方规费与具体开销项（具体金额），周期只标在各流程步骤上；**禁止**「总费用 20–50 万」「总周期 2.5–4.5 年」这类无信息量的大区间
2. **辖区全覆盖**：收录一个国家就要收录其全部省/州/领地；不运作地方提名的辖区（如努纳武特）也要建 region 文件并在 `policyOverview` 里说明实际情况
3. **项目跟着省走**：项目必须挂到所属省/州（`region` 字段）；联邦项目才允许省略 `region`
4. **每个项目必须给官方来源**，用户核对是最后一道防线
5. **政策收紧期**：项目暂停/关停时把 `status` 改为 `paused`，页面会展示灰色徽章而不是删除内容
6. **诚实标注**：不确定的细节写「以官方为准」，宁可少写不可写错
